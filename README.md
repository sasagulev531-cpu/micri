# FCP-Jobs — Работа шахтёра, добываемые узлы и система кастомных заданий (`quests.yml`)

Плагин `FCP-Jobs` (`Paper 1.21.x`, Java 21) реализует работу шахтёра с настраиваемыми многостадийными узлами, жёлтой контурной подсветкой граней и гибкой системой кастомных заданий и многоэтапных цепочек, настраиваемых через `plugins/FCP-Jobs/quests.yml`.

---

## 1. Команды и права (Permissions)

| Команда | Право | Описание |
|---|---|---|
| `/work`, `/workmenu` | — | Открыть главное меню работы «Шахтёр» (начать смену / открыть задачи / уволиться) |
| `/quests` | `fcp.jobs.quests` | Открыть меню задач шахтёра (также открывается по кнопке в `/work`, слот 12) |
| `/setgranic` | `fcp.admin.jobs.region` | Задать углы `pos1`/`pos2` рабочей зоны шахты |
| `/mnode wand` (`/miningnode wand`) | `fcp.admin.jobs.node` | Выдать маркер узла шахты (ЛКМ/ПКМ — создать/открыть, Shift+ЛКМ — первая точка области, ПКМ в воздух — шаблон по умолчанию) |
| `/mnode fill [МАТЕРИАЛ]` | `fcp.admin.jobs.node` | Массово зарегистрировать узлы в выделенной области |
| `/mnode cleararea` | `fcp.admin.jobs.node` | Удалить все узлы внутри выделенной области |
| `/mnode applyall` | `fcp.admin.jobs.node` | Применить текущий шаблон стадий/кулдауна/лута ко всем узлам |
| `/mnode reload` | `fcp.admin.jobs.node` | Перезагрузить `quests.yml`, `hrabota.yml` и `mining-nodes.yml` без рестарта сервера |
| `/mnode validate` | `fcp.admin.jobs.node` | Проверить конфигурацию и все узлы на ошибки |

## 2. Подробная документация по `plugins/FCP-Jobs/quests.yml`

Все задания настраиваются **кодом в конфиге** `plugins/FCP-Jobs/quests.yml` (файл автоматически создаётся при первом запуске плагина).  
После любого изменения файла достаточно выполнить в игре или консоли:
```text
/mnode reload
```

### 2.1. Как работает механика «Взять задание» (`require-accept`)
- **Обычные задания, касающиеся шахты (`require-accept: false`)** — активны **сразу автоматически**. Игроку не нужно нажимать лишних кнопок: он просто устраивается на смену (`/work`) и копает руду в шахте, а прогресс засчитывается сам.
- **Сложные и еженедельные цепочки (`require-accept: true`)** — чтобы прогресс начал считаться, игрок **обязан открыть меню задач (`/work` → «Задачи шахтёра» или `/quests`) и нажать ЛКМ по карточке задания** («▶ НАЖМИТЕ ЛКМ, ЧТОБЫ ВЗЯТЬ ЗАДАНИЕ»).  
  Пока задание не взято — никакие действия (добыча, переплавка, крафт) в него **не идут**.

---

### 2.2. Общая структура `quests.yml`

```yaml
enabled: true                  # Включена ли система заданий (true / false)
timezone: "Europe/Moscow"      # Часовой пояс сброса (00:00 для daily, ПН 00:00 для weekly)

daily:
  count: 3                     # Сколько ежедневных задач выдавать игроку из пула (1..7)
  pool:                        # Список всех возможных ежедневных задач
    - ...

weekly:
  count: 3                     # Сколько еженедельных задач/цепочек выдавать игроку из пула (1..7)
  pool:                        # Список всех возможных еженедельных цепочек
    - ...
```

### 2.3. Все поля одного задания в `pool`

| Поле | Обязательно | По умолчанию | Описание |
|---|---|---|---|
| `id` | **Да** | — | Уникальный английский идентификатор задания (например, `weekly_iron_master`). Не меняйте `id` у уже выданного задания, если хотите сохранить прогресс игроков. |
| `title` | Нет | авто | Название задания в меню (поддерживает цветовые коды `&6`, `&l` и т.д.). |
| `icon` | Нет | `BOOK` / `WRITTEN_BOOK` | Материал иконки в меню `/quests` на английском (`IRON_INGOT`, `RAW_GOLD`, `BLAST_FURNACE` и т.д.). |
| `description` | Нет | пусто | Описание (строка или список строк `- "&7Текст"`), отображается вверху лора карточки. |
| `require-accept` | Нет | `false` для `daily` (шахта), `true` для `weekly` и цепочек | Нужно ли игроку вручную нажать **ЛКМ «Взять задание»** в меню, чтобы пошёл зачёт. |
| `reward` | Нет | `0` | Награда в монетах через `FCP-EconomyMarket` (`EconomyService.addCoins`). |
| `reward-items` | Нет | `[]` | Список предметов в награду в формате `"MATERIAL КОЛИЧЕСТВО"` (например, `- "DIAMOND 2"`). Если инвентарь полон — выпадут под ноги игроку. |
| `reward-commands` | Нет | `[]` | Список консольных команд при завершении задания. Поддерживаются плейсхолдеры `%player%` и `%uuid%` (без `/` в начале). |
| `steps` | Да (для цепочки) | — | Список последовательных этапов (см. раздел 2.5). Если задание состоит из 1 действия, можно писать `type`, `material`, `amount` прямо на верхнем уровне без `steps`. |

---

### 2.4. Английские типы целей (`type`)

Все типы этапов пишутся **на английском языке** (регистр не важен):

| `type` в конфиге | Нужен ли `material`? | По умолчанию `require-working` | Что именно засчитывается |
|---|---|---|---|
| `MINE` | Да (`RAW_IRON`, `COAL`, `COBBLESTONE` или `ANY`) | `true` (на смене в шахте) | Предметы, выпавшие игроку из разработанных узлов шахты. |
| `BREAK` | Да (`STONE`, `TUFF`, `DEEPSLATE` или `ANY`) | `true` (на смене в шахте) | Сломанные блоки/стадии в шахте (`ANY` — любой блок шахты). |
| `COMPLETE_NODES` | Нет | `true` (на смене в шахте) | Количество полностью разработанных (доведённых до истощения) узлов шахты. |
| `SMELT` | Да (`IRON_INGOT`, `GOLD_INGOT`, `COPPER_INGOT`, `ANY`) | `false` (где угодно) | Переплавленные предметы, которые игрок забирает из печи / плавильни / коптильни. |
| `CRAFT` | Да (`IRON_BLOCK`, `GOLDEN_APPLE`, `IRON_PICKAXE`, `ANY`) | `false` (где угодно) | Реально скрафченные предметы на верстаке или в сетке инвентаря (с защитой от накрутки при полном инвентаре). |
| `OBTAIN` | Да (`IRON_INGOT` и т.д. или `ANY`) | `false` | Получение предмета любым из путей: добыча в шахте + выплавка в печи + крафт. |
| `EARN_COINS` | Нет | `true` (на смене в шахте) | Количество монет, заработанных непосредственно во время смены в шахте. |

- **`amount`**: любое целое число от **`1` до `65536`** (`2^16`).
- **`material: ANY`** (или `*`): засчитывает любой материал данного действия (например, `type: BREAK`, `material: ANY` — сломать любые блоки в шахте).
- **`require-working: true / false`**:
  - если `true` — действие засчитывается **только когда игрок устроен на смену (`/work`) и находится внутри границ шахты (`/setgranic`)**;
  - если `false` — действие можно выполнить где угодно (например, пойти домой к своим печам и переплавить руду или скрафтить блоки на верстаке).

---

### 2.5. Как работают многоэтапные цепочки (`steps`)

Когда у задания указан список `steps`, этапы выполняются **строго по очереди**:
1. Игрок открывает `/quests` (или `/work` → «Задачи шахтёра») и нажимает **ЛКМ**, чтобы взять задание (`require-accept: true`).
2. Открывается **Этап 1** (`▶` в меню). Пока Этап 1 не выполнен полностью (например, `0/64 RAW_IRON`), Этап 2 (`🔒`) заблокирован и заранее накрутить его нельзя.
3. Как только Этап 1 достигает `64/64`, игрок слышит звук повышения уровня, получает уведомление в чат о переходе ко **2-му этапу**, а прогресс переключается на Этап 2 (`SMELT IRON_INGOT 64`).
4. Когда завершается **последний этап** цепочки — задание помечается выполненным и игроку выдаются все награды (`reward`, `reward-items`, `reward-commands`).

В меню `/quests` цепочка наглядно отображается по шагам:
- `✔ 1. Добыть 64 рудного железа на смене в шахте (64/64)` — завершённый этап;
- `▶ 2. Переплавить 64 железных слитка в печи (18/64)` — текущий активный этап;
- `🔒 3. Скрафтить 7 железных блоков (0/7)` — следующий закрытый этап.

### 2.6. Готовые примеры для `plugins/FCP-Jobs/quests.yml`

#### Пример А: Обычное ежедневное задание шахты (считается само без взятия)
```yaml
daily:
  count: 3
  pool:
    - id: daily_coal_32
      title: "&fЧёрное золото"
      icon: COAL
      require-accept: false      # Считается автоматически во время работы в шахте!
      reward: 350
      description:
        - "&7Добудьте уголь из узлов шахты."
      type: MINE
      material: COAL
      amount: 32
```

#### Пример Б: Сложное еженедельное задание с цепочкой (взять → накопать в шахте → переплавить → скрафтить)
```yaml
weekly:
  count: 3
  pool:
    - id: weekly_iron_chain
      title: "&6&lМастер железа"
      icon: IRON_INGOT
      require-accept: true       # Пока игрок не нажмёт ЛКМ в меню — прогресс НЕ идёт!
      reward: 3000
      reward-items:
        - "DIAMOND 2"
      reward-commands:
        - "give %player% experience_bottle 16"
      description:
        - "&7Пройдите полный цикл кузнеца:"
        - "&7руда из шахты → слитки в печи → железные блоки!"
      steps:
        # Шаг 1: обязательно работая на смене в шахте, добыть 64 рудного железа
        - type: MINE
          material: RAW_IRON
          amount: 64
          require-working: true
          title: "Добыть 64 рудного железа на смене в шахте"

        # Шаг 2: переплавить 64 слитка в любой печи или плавильне (можно вне шахты)
        - type: SMELT
          material: IRON_INGOT
          amount: 64
          require-working: false
          title: "Переплавить 64 железных слитка в печи"

        # Шаг 3: скрафтить 7 железных блоков на верстаке
        - type: CRAFT
          material: IRON_BLOCK
          amount: 7
          require-working: false
          title: "Скрафтить 7 железных блоков"
```

## 3. Защита рабочей зоны шахты и совместимость

- **Защита от неустроенных игроков:** если игрок находится внутри шахты (`/setgranic`), но не устроен на работу через `/work`, он **не может сломать ни один блок** — на экране появляется предупреждение **«Устройтесь на работу!»** и проигрывается ворчание жителя (`entity.villager.no`).
- **Авто-увольнение при выходе из зоны:** если работающий шахтёр покидает пределы шахты (пешком, телепортом или сменой мира), смена автоматически завершается, а заработанные монеты выплачиваются.
- **Работа без плагина экономики:** `FCP-EconomyMarket` указан в `softdepend` — если экономика временно отсутствует, плагин и меню `/work` продолжают стабильно работать, а невыплаченные награды за квесты можно забрать позже кнопкой «Проверить награды» в `/quests`.

## 4. Файлы конфигурации и данных

- `plugins/FCP-Jobs/quests.yml` — **конфиг всех ежедневных и еженедельных заданий и цепочек** (редактируется администратором, перезагружается через `/mnode reload`).
- `hrabota.yml` — границы шахты (`pos1`/`pos2`), цены руд, шаблон узлов по умолчанию и настройки частиц.
- `mining-nodes.yml` — база созданных узлов шахты.
- `mining-quests.yml` — сохранённый прогресс игроков по взятым заданиям и этапам цепочек.
