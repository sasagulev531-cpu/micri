# FCP-Jobs — Шахтёр, настраиваемые узлы и гибкая система заданий v2 (`quests.yml`)

Плагин `FCP-Jobs` (`Paper 1.21.x`, Java 21) реализует работу **Шахтёра (`MINER`)** с настраиваемыми многостадийными добываемыми узлами, контурной подсветкой граней, защитой от потери заработка смены при рестарте и декларативным языком заданий **`quests.yml` v2** (с полной обратной совместимостью с форматом v1).

> **Примечание по видам работы (согласовано с владельцем):** в текущем релизе в игре активна **только работа `MINER` («Шахтёр»)**. Внутри кода заложены расширяемые реестры `JobRegistry` и `ActionKindRegistry`, чтобы будущие виды работ можно было подключить без переписывания ядра заданий.

## 1. Команды и права (Permissions)

| Команда | Право | По умолчанию | Описание |
|---|---|---|---|
| `/work`, `/workmenu` | — | все | Открыть меню работы «Шахтёр» (начать смену / открыть задачи / завершить смену) |
| `/quests` | `fcp.jobs.quests` | `true` | Открыть меню заданий шахтёра (54 слота, страницы, взятие ЛКМ, проверка наград) |
| `/questsadmin validate` (`/qadmin validate`) | `fcp.admin.jobs.quests` | `op` | Полный отчёт валидации `quests.yml`, периодов, реестров и белого списка команд |
| `/questsadmin reload` (`/qadmin reload`) | `fcp.admin.jobs.quests` | `op` | Перезагрузить `quests.yml` и синхронизировать пулы без рестарта сервера |
| `/setgranic` | `fcp.admin.jobs.region` | `op` | Задать точки `pos1`/`pos2` рабочей зоны шахты |

| `/mnode validate` / `/mnode questvalidate` | `fcp.admin.jobs.node` | `op` | Проверить все узлы шахты / вывести отчёт валидации `quests.yml` |

## 2. Полная грамматика `plugins/FCP-Jobs/quests.yml` (формат v2)

При первом запуске (если `plugins/FCP-Jobs/quests.yml` отсутствует) плагин создаёт рабочий `quests.yml` и эталонный `quests.example.yml` с **16 готовыми заданиями шахтёра**. Существующий `quests.yml` (как v2, так и старый v1 `daily.pool`/`weekly.pool`) **никогда не перезаписывается** и читается автоматически.

### 2.1. Каркас файла `quests.yml` v2

```yaml
version: 2
enabled: true

defaults:
  timezone: "Europe/Moscow"     # Часовой пояс сброса периодов
  accept: auto                  # auto (считается сразу) | manual (нужно нажать ЛКМ «Взять задание»)
  require-working: true         # Шахтные условия требуют активной смены в зоне шахты

security:
  reward-commands-whitelist: [] # Белый список префиксов команд (пустой [] = команды отключены)

periods:
  daily:   { template: daily,    count: 3 }
  weekly:  { template: weekly,   count: 3 }
  monthly: { template: interval, days: 30, count: 1 }

quests:
  - id: my_custom_code          # Свободный уникальный идентификатор задания
    title: "&6Название задания"
    icon: IRON_PICKAXE
    category: weekly            # Имя периода из periods (или once)
    accept: manual              # auto | manual
    description:
      - "&7Описание карточки в меню /quests."
    requires:                   # Опционально: все указанные условия должны выполняться
      quest: null               # ID задания, которое должно быть выполнено и оплачено
      job: MINER                # Вид работы игрока
      permission: null          # Нода прав (например, fcp.rank.vip)
    steps:                      # Последовательные шаги (1..N)
      - name: "Шаг 1"
        all:                    # AND-группа (либо all, либо any + any-amount)
          - { event: MINE, material: RAW_IRON, amount: 64, min-depth: -64, max-depth: 80 }
        time:                   # Опционально: время на активной смене в шахте
          as-job: MINER
          minutes: 20
    rewards:
      coins: 2500
      items:
        - { material: DIAMOND, amount: 2, chance: 1.0 }
        - { material: EMERALD, amount: 3, chance: 0.5 }
      commands: []
    on-complete:
      unlock: []                # ID разовых (once) заданий, открывающихся после выполнения и выплаты
```

---

### 2.2. Реестр событий (`event`)

| `event` (и алиасы) | Нужен `material`? | `require-working` по умолчанию | Описание |
|---|---|---|---|
| `MINE` (`LOOT`, `COLLECT_LOOT`, `LOOT_AMOUNT`) | Да (`RAW_IRON`, `COAL`, `ANY`) | `true` | Добыча предметов из лута узлов шахты |
| `BREAK` (`BREAK_BLOCK`) | Да (`STONE`, `DEEPSLATE`, `ANY`) | `true` | Разрушение стадий узлов и руд в шахте |
| `COMPLETE_NODES` (`NODES`, `NODES_COMPLETED`) | Нет | `true` | Полная разработка узлов шахты до истощения |
| `SMELT` (`FURNACE`, `SMELT_ITEM`) | Да (`IRON_INGOT`, `GOLD_INGOT`, `ANY`) | `false` | Извлечение переплавленных предметов из печи/плавильни |
| `CRAFT` (`CRAFT_ITEM`) | Да (`IRON_BLOCK`, `GOLDEN_APPLE`, `ANY`) | `false` | Крафт предметов (с защитой от накрутки при полном инвентаре) |
| `OBTAIN` (`GET`, `OBTAIN_ITEM`) | Да (`IRON_INGOT`, `ANY`) | `false` | Получение предмета любым путём (`MINE` + `SMELT` + `CRAFT`) |
| `EARN_COINS` (`COINS`, `EARN_MONEY`) | Нет | `true` | Монеты, заработанные за смену в шахте |
| `JOB_ACTION` (`WORK_ACTION`) | Нет | `true` | Рабочие действия на смене (с фильтром `job: MINER`) |

Дополнительные параметры любого условия:
- `amount`: целое число от **`1` до `65536`**.
- `min-depth` / `max-depth`: ограничение по высоте `Y` блока (`Y >= min-depth` и `Y <= max-depth`).
- `job`: учитывать действия только указанного вида работы (`MINER`).
- `require-working`: `true` / `false` — переопределение требования находиться на активной смене в шахте.

---

### 2.3. Семантика шагов (`all`, `any`, `time`) и переходов

- **`all` (И-группа):** у каждого условия своя цель `amount`; шаг закрывается, когда выполнены **все** условия списка. В GUI показывается прогресс каждого условия отдельно.
- **`any` (ИЛИ-группа):** задаётся общая цель `any-amount: N`; прогресс от любого подходящего условия из `any` суммируется в общий счётчик до `N`. Указывать `all` и `any` в одном шаге одновременно запрещено (ловит валидатор).
- **`time: { as-job: MINER, minutes: M }`:** накапливает минуты, проведённые игроком на активной смене внутри границ шахты. Может использоваться самостоятельно или вместе с `all` / `any`.
- **Переход между шагами без переноса остатка:** шаги выполняются строго по очереди (`0 → 1 → ...`). Избыточный прогресс предыдущего шага **не переносится** в следующий шаг.

---

### 2.4. Периоды (`periods`) и разблокировки (`once` + `unlock`)

- `daily` — сброс в `00:00` по `defaults.timezone`, случайная выборка `count` заданий без повторов.
- `weekly` — сброс в понедельник `00:00` (ISO-неделя), случайная выборка `count` заданий.
- `interval` — индивидуальный сброс каждые `days` дней с момента первой выдачи игроку.
- `once` — разовые задания: не сбрасываются, а после полного выполнения и выплаты награды скрываются навсегда. Если задание указано в `on-complete.unlock` другого задания (или имеет `requires.quest`), оно находится в статусе `LOCKED` (`🔒`) и разблокируется **только после выполнения и успешной выплаты** предыдущего задания.

Проверка смены периодов выполняется лениво при обращении к профилю игрока (без лишних фоновых таймеров).

## 3. Безопасность, надёжность выплат и режим закрытой шахты

1. **Белый список наградных команд (`security.reward-commands-whitelist`):**
   - По умолчанию список пуст (`[]`) — ни одна консольная команда из `rewards.commands` **не исполняется** (в лог пишется предупреждение, а монеты и предметы выдаются штатно).
   - Чтобы разрешить конкретные команды, укажите префиксы, например: `reward-commands-whitelist: ["fcp give"]`. Команды с `;`/переводами строк и команды вне префиксов блокируются.
2. **Гарантия однократной выплаты и повторы при сбое экономики:**
   - Деньги начисляются исключительно через `EconomyService`. Флаг `paid` после успешной выплаты никогда не сбрасывается.
   - Если `FCP-EconomyMarket` временно недоступен, невыплаченная награда за задание или зарплата за смену пытается начислиться автоматически каждые **30 секунд** в течение максимум **30 минут** (после чего пишет уведомление администратору в лог), а также доступна вручную по кнопке **«Проверить награды»** в `/quests`.
3. **Персистентность смены и заработка (`work-sessions.yml`):**
   - Заработок текущей смены сохраняется на диск с дебаунсом (не чаще 1 раза в 5 секунд) и синхронно сбрасывается при `onDisable`. При рестарте или краше сервера накопленные монеты смены не теряются и автоматически выплачиваются игроку.
4. **Режим закрытой шахты:**
   - Если зона шахты в `hrabota.yml` ещё не задана (`pos1`/`pos2` отсутствуют), мир выгружен или узлов `0` — плагин штатно запускается, команды `/work`, `/quests`, `/questsadmin` открываются без ошибок и без спама в консоль, а шахтный прогресс просто не начисляется до открытия шахты.

## 4. Файлы плагина

- `plugins/FCP-Jobs/quests.yml` — основной конфиг заданий v2 (или совместимый v1).
- `plugins/FCP-Jobs/quests.example.yml` — справочный пример конфига v2 с 16 заданиями шахтёра.
- `plugins/FCP-Jobs/hrabota.yml` — координаты зоны шахты (`pos1`/`pos2`) и параметры узлов/частиц.
- `plugins/FCP-Jobs/mining-nodes.yml` — сохранённые узлы шахты.
- `plugins/FCP-Jobs/mining-quests.yml` — прогресс игроков по заданиям и цепочкам (дебаунс записи ≤ 1 раз / 5 с).
- `plugins/FCP-Jobs/work-sessions.yml` — сохранённый заработок активных смен и очередь довыплат.
